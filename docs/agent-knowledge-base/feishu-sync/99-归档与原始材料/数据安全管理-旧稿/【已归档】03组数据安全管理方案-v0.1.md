一、目的与适用范围
规范本课题（MEM-AIVisdefect / 03 组 - V 公司拉挤外观检测）在飞书云盘、Git 仓库、坚果云及现场介质上的数据分类、权限、脱敏、存放、同步与应急处理，降低外泄与版本混乱风险。
适用：飞书知识空间与共享盘、GitHub 仓库 MEM-AIVisdefect、组内坚果云、raw-data、报销票据影像件、对外 / 对上交付材料。
不适用：个人电脑本地草稿（未入库前由个人自管，入库必须过本方案与《资料入库规范》）。
二、原则（已对齐仓库口径）
企业 / 自有数据默认不公开（NFR-4）；
对外脱敏一律写「V 公司」（D-01）；禁止真实客户全称、简称、logo 文字；
Git 仓库是文档之源；飞书是协作面；大图 / 视频走坚果云；
禁止个人 Agent 灵魂文件入库：SOUL.md/ AGENTS.md 等（D-06）；
最小必要：谁需要谁可见；对外分享默认关闭。
三、数据分类与存放

分工口径（与群聊约定一致，待写入手册关单）：
坚果云：图片、视频、大文件库
飞书：目录、需版本控制的文档与小附件
Git：文档权威源 + 可版本化的代码 / 规范 / 清单；大文件不进仓
四、飞书侧安全控制
空间命名含「V 公司」，禁止出现真实客户名（见《飞书空间搭建手册》）
权限基线（建议，待关单）：
项目组全员：可编辑
校友导师：可评论
对外分享（链接 / 组织外）：默认关闭；确需开放须范汝杰 + 郭小川双确认，且仅限脱敏冻结版
10-现场与工艺资料/：限核心成员
08-项目管理/报销票据影像件/：限樊晶、范汝杰、郭小川
入库前置：命名合规、已脱敏、版本档位已标（见《资料入库规范》三问）
红线：
未脱敏原件、未去标识现场图不得进工作区
＞100MB 原始视频不进飞书；只放剪辑片段 / 抽帧图 + 坚果云索引说明
禁止上传无关个人文件、禁止 SOUL/AGENTS 类文件
五、Git / 检测数据安全
仓库私有为前提；企业检测数据、原图、客户标识不得公开仓库或公开站点外传
raw-data：只增不改、按版本子目录；纠错出新版本；实验绑定「数据版本 + commit + 模型版本 + 指标」
权重与大体积产物：记哈希 / 路径，不把大文件塞进文档树；训练 / 推理按内网离线规范执行
BI / 公网看板：只放管理信息；企业检测明细默认不公开（NFR-4）
意见箱等含敏感吐槽的内容：入 git 前再脱敏（姓名 / 产线等替换）
六、脱敏与外发入库前必须处理：
客户名 → V 公司
V 公司联系人 → 角色代称（如「V 公司工艺主管」），不写真名 / 电话 / 微信
现场图：人脸、工牌、厂牌、设备铭牌、车牌、门牌等去标识
工艺参数：禁止擅自外发
外发条件：
仅冻结版（vX.Y）可对外 / 对上
双周报、任务书脱敏版、发布检查单等同此规则
宣传材料须按课程规则先过执行组老师审核；禁止截图外传未脱敏内容
七、同步与备份
飞书 → Git：现有半自动 npm run sync-docs（主要 docx/doc），落点 docs/agent-knowledge-base/feishu-sync/
Git → 飞书：仍人工 / 评审后回写；冻结版两边须一致，冲突以仓库为准
坚果云 ↔ 飞书：大媒体不进飞书正文；飞书保留索引（存放位置、日期、机位、摘要）；同步节奏由资料管理员约定（不必高频）
每周抽查：范汝杰周会后抽查新增文件；违规 48h 内整改或移 99-归档与原始材料/待整改区
八、角色与责任
范汝杰：空间与入库规范 Owner；权限与抽查；本方案关单人
各文档 Owner：脱敏、版本档位、飞书↔仓库一致性
樊晶：报销票据影像件保管与台账
郭小川：对外分享双确认之一；现场 / 核心资料协同
全员：上传前自检；发现真实客户名或未打码图立即停用并通知范汝杰
九、事件与应急（建议流程）发现疑似外泄 / 误传真实客户名 / 误开外链时：
立即取消外链或收回权限
在群内通知范汝杰 + 郭小川，记录时间、文件、影响范围
原件移受限区；工作区替换为脱敏版
周会通报原因与整改，必要时升版本并重审相关冻结版
十、检查清单（每次入库 / 外发前）
回复 (2/2)
 无真实客户名 /logo/ 未脱敏人名电话
 现场图已去标识
 级别与文件夹匹配（L2/L3/L4 未放错位置）
 大视频在坚果云，飞书仅索引或小片段
 版本档位正确；对外仅冻结版
 无 SOUL.md/ AGENTS.md
 外链默认关闭，或已双确认
