一、目的与适用范围
规范本课题（MEM-AIVisdefect / 03组-V公司拉挤外观检测）在飞书云盘、Git 仓库、坚果云及现场介质上的数据分类、权限、脱敏、存放、同步与应急处理，降低外泄与版本混乱风险。
适用：飞书共享盘与知识空间、GitHub 仓库 MEM-AIVisdefect、组内坚果云、raw-data、报销票据影像件、对外/对上交付材料。
不适用：个人电脑本地草稿（未入库前由个人自管；入库必须过本任务与《资料入库规范》）。
二、原则（已对齐仓库口径）
企业/自有数据默认不公开（NFR-4）
对外脱敏一律写「V公司」（D-01）；禁止真实客户全称、简称、logo 文字
Git 仓库是文档之源；飞书是协作面；大图/视频走坚果云
禁止个人 Agent 灵魂文件入库：SOUL.md / AGENTS.md 等（D-06）
最小必要：谁需要谁可见；对外分享默认关闭
密钥与 Token（GitHub PAT、云主机口令等）禁止发到群聊；只进各自系统的密码栏

四、飞书侧安全控制
空间/文件夹命名含「V公司」，禁止真实客户名
权限基线（建议，待关单）：项目组可编辑；校友导师可评论；对外分享默认关闭（范汝杰+郭小川双确认例外）；现场/工艺限核心成员；票据夹限樊晶/范汝杰/郭小川
入库前置三问：命名合规？已脱敏？版本档位已标？
红线：未脱敏原件不得进工作区；＞100MB 原始视频不进飞书；禁止 SOUL/AGENTS
五、Git / 检测数据安全
仓库私有；raw-data 只增不改按版本；实验绑定数据版本+commit+模型版本+指标；BI 不含企业检测明细；意见箱入 git 前再脱敏。
六、脱敏与外发
客户名→V公司；联系人用角色代称；现场图去标识；仅冻结版可对外/对上；宣传材料先过执行组审核。
七、同步与备份
飞书→Git：npm run sync-docs；Git→飞书人工回写，冲突以仓库为准；坚果云大媒体不进飞书正文；范汝杰周会后抽查，违规 48h 整改。
八、角色与责任
范汝杰：Owner/抽查/关单。各文档 Owner：脱敏与一致性。樊晶：票据。郭小川：外部分享双确认与现场资料。全员：上传自检。
九、事件与应急
取消外链→通知范汝杰+郭小川→原件移受限区并换脱敏版→周会通报。
